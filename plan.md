## 0. Review of gpt-feedback.md against the actual repository

The feedback was clearly written after inspecting the repo — it names the real
mechanisms (`svg.setCurrentTime`, `useDemoClock`, `encoder.mjs`, playback
assertions) and its core constraint (no second pipeline) matches how the repo
is built. Assessment per item:

### Accept as-is
- **No second rendering pipeline.** The repo already has exactly one shared
  capture path (`scripts/lib/encoder.mjs` → `captureLoop` + `encodeFrames`) with
  two front-ends. The infographic system is a third *authoring mode* feeding the
  same SMIL path (`svg-to-gif.mjs`), not a new engine.
- **Three-concern separation** (content / layout / animation). Justified: the
  existing `architecture/gen.ts` is a 400+ line monolith mixing content,
  coordinates, phase curves, and SVG emission. The new system should not repeat
  that.
- **Theme/token mechanism.** Existing diagrams hardcode a `C = {...}` palette
  per diagram. A shared token system with per-artifact override is justified.
- **viewBox + vector source, exportable at multiple resolutions.** The repo
  already supports `--width/--height` overrides at capture; the SVG stays vector.
- **Determinism requirements.** Already guaranteed by the pipeline (SMIL seek,
  no wall-clock, no network). Stated as an invariant, not new work.
- **"Source artifacts are the product; GIF/Video exports are compiled
  artifacts."** Adopt as documented invariant.
- **Diagram vs. mockup decision rule** (SVG artifact for conceptual/system-level,
  React for product-UI demonstration). Adopt in README.
- **Reference artifact with fictional/general terminology** — no product claims.
- **Animation as explanation, not decoration** — fade/slide/reveal/pulse,
  sequential, restrained.

### Adapt to repo conventions (do not import the feedback's structure literally)
- **Directory layout.** Feedback suggests
  `diagrams/<name>/{gen.ts, layout.ts, animation.ts, playback.test.ts}` and a
  `client/company-a/...` tree. The repo convention is:
  - artifact lives at `src/diagrams/<name>/` with `gen.ts` as entry point and
    the committed `src/diagrams/<name>/<name>.svg` generated by `npm run gen`
    (`scripts/gen-all.mjs` auto-discovers every dir with a `generate()` export);
  - assertions live in `scripts/check-<name>.mjs` (structural/timing) and
    `scripts/playback-<name>.mjs` (rendered-GIF behavior) — there is no
    `*.test.ts` convention here;
  - `client/company-a/...` becomes a documented future convention, not a
    scaffolded directory (no clients exist yet).
- **`<svg>` root must keep explicit `width`/`height` attributes.** 
  `svg-to-gif.mjs` derives native capture size by regex-matching
  `width="N" height="N"` on the root element. So: `width` + `height` + `viewBox`
  all present (composition targets `viewBox`, capture size defaults to the
  attributes, `--width/--height` override at export).
- **Gen-time TS runs under Node native type-stripping** (Node ≥ 23.6): erasable
  syntax only (no `enum`, no namespaces, no parameter properties), relative
  imports only (no path aliases at gen time — Vite aliases exist only in the
  browser).
- **Theme is dark-first.** The repo's capture default is `scheme: dark`
  (`svg-to-gif.config.json`), black page background. Default theme = dark;
  light is a per-artifact override if ever needed.
- **`DemoTimeline`**: keep as a documented conceptual invariant (SMIL seek ↔
  demo-clock step), do not refactor the encoder or the React hook.
- **gen-all.mjs needs one small change** if the shared lib lives under
  `src/diagrams/` (see §3): skip directories that have no `gen.ts` instead of
  printing a spurious error.

### Reject / defer
- Do **not** create all ~20 listed primitives blindly — only those justified by
  the reference artifact (see §3).
- Do **not** introduce a DSL — TypeScript with a small phase-timeline builder
  (generalizing `architecture/gen.ts`'s `curve()`) is sufficient.
- Do **not** scaffold `client/` directories now; document the convention.
- Do **not** touch the mockup pipeline, encoder core, or Playwright usage.

## 3. Shared authoring layer — `src/diagrams/shared/`

Plain TS (Node type-stripping compatible, relative imports only, zero
dependencies). Sized to the reference artifact — no speculative generality.

### 3.1 `timing.ts` — unified SMIL helpers
Extract the duplicated helper sets from the two existing generators (hero:
`kt`, `fadeIn`, `slideIn`, `showWindow`, `showFrom`, `fadeFrom`, `pulse`;
architecture: `curve`/`op`/`stroke` phase builder) into one module:

- `kt(t, T)` — keyTime fraction.
- `fadeFrom(a, T, fade)`, `showFrom(a, T)`, `showWindow(a, b, T)`,
  `slideIn(a, T, from=6)`, `fadeWindow(a, b, T)`, `pulse(values, dur)` —
  same semantics as hero's, generalized.
- `phaseCurve(fn, phases, T, fade)` — generalizes architecture's `curve()`:
  given a phase table `[{ phase, t }]` and a per-phase value fn, produce
  `keyTimes`/`values` with zero-length segments for instant steps. This is the
  highest-leverage abstraction: it makes timings explicit and inspectable (AI/
  LLM usability requirement) and maps 1:1 onto the semantic animation model.
- `Timeline` type documenting the invariant:
  `{ duration, fps, timeForFrame(frame): number }` — conceptual only, shared
  between the SMIL world (`setCurrentTime`) and React world (`useDemoClock`).

### 3.2 `theme.ts` — tokens
```ts
interface InfographicTheme {
  background: string
  surface: string        // panel/card fill
  surfaceAlt: string     // nested zone fill
  border: string
  text: string
  mutedText: string
  faintText: string
  accent: string         // primary column accent
  accentSurface: string  // tinted panel fill
  header: string         // column header fill
  arrow: string
  highlight: string      // pulse/emphasis color
  // plus per-primitive conveniences used by layout.ts (e.g. badge, numberRing)
}
```
`darkTheme` default (slate-based, consistent with existing diagrams). Artifact
overrides via its own `theme.ts` (or inline object) — no primitive code change.

### 3.3 `layout.ts` — composition primitives
Justified by the reference artifact's repeated structure only:
- `Column(x, y, w)` — column origin + vertical-rhythm helpers (consistent
  spacing, equal widths via a shared grid).
- `Panel(...)` — rounded rect with optional header stripe, title, subtitle,
  border (the existing card look: `rx=10..12`, 4px accent stripe).
- `Stage(...)` — numbered pipeline stage: number ring/badge + icon + label +
  optional sublabel (the repeated unit across all three columns).
- `Arrow(...)` / `Connector(...)` — vertical/elbow arrows between stages;
  chevron/line + marker, plus support for an `animateMotion` data-dot along a
  defined path (existing pattern from architecture).
- `Badge`, `Label`, `Metric`, `BestForPanel` (title + bullet list), `Header`.
- All builders emit stable `data-role` / `data-stage` attributes on groups —
  the check scripts and future LLM inspection hook into these instead of
  reverse-engineering coordinates.

### 3.4 `icons.ts` — line icons
Small stroke-based icon fragments using the repo's existing pattern
(hero uses nested `<svg viewBox="0 0 24 24">` with lucide-style paths):
user, users, server, database, browser, code, chart, cache, queue, device,
response/check, arrow. Themed via `stroke="currentColor"`-style token.

### 3.5 `svg.ts` — document assembly
- `doc({ W, H, theme, body, defs, fontStack })` — emits the root
  `<svg width height viewBox>` (width/height attributes mandatory for the
  capture script's native-size regex), `<style>` (font stack from existing
  diagrams: DejaVu Sans / system), `<defs>`.
- `pipelineDotPath(d, color, begins, dur)` — the moving-data-dot helper
  (circle + `animateMotion` + `<mpath>`, staggered begins).

**gen-all.mjs change (only pipeline-file edit):** skip dirs without `gen.ts`
(`existsSync` check) so `src/diagrams/shared/` doesn't produce a spurious error.

## 4. Reference artifact — `src/diagrams/serving-approaches/`

Name TBD (see §10). Content is the feedback's conceptual comparison, expressed
in fictional/general terms — no claims about real products.

### 4.1 `content.ts` — semantic content (what it says)
```ts
interface ColumnContent {
  id: 'local' | 'throughput' | 'structured'
  header: string
  headerSub?: string
  actors: { label: string; sublabel?: string; icon: IconName }
  stages: { label: string; sublabel?: string; icon: IconName }[]
  result: { label: string; sublabel?: string; icon: IconName }
  bestFor: { title: string; items: string[] }
}
const CONTENT: ColumnContent[] = [
  // Local Runtime:  local user → request queue → local model → response
  //   best for: local development, experimentation, single-user, constrained hardware
  // High Throughput: concurrent users → request batching → memory/cache mgmt → response
  //   best for: production APIs, high request volume, GPU utilization, concurrency
  // Structured Workflows: concurrent users → request scheduler → shared context/cache → structured response
  //   best for: agents, multi-step workflows, multi-turn, structured output
]
```

### 4.2 `layout.ts` — placement (where things go)
- Portrait composition, `viewBox="0 0 480 580"` (feedback's target), three
  equal columns (~140px each, 16px gutters, 24px outer margin).
- Per column, top-to-bottom rhythm: header → actors → stage 1 → arrow →
  stage 2 → arrow → result → best-for panel.
- Typography: 12–13px headers, 10–11px labels, 9–10px sublabels/best-for —
  readable at 480-wide output, crisp via dpr-2 capture.
- If 480×580 proves cramped during render inspection, the same layout functions
  parameterize to a larger composition (e.g. 560×680) with no content changes —
  decide from rendered frames, fix source, not encoder.

### 4.3 `animation.ts` — timeline (when things change)
Semantic schedule, explicit data, all keyTimes relative to `T`:

| t (s) | event |
|-------|-------|
| 0.0   | headers fade in (column 1 → 3, staggered 0.15s) |
| 0.3   | actor icons appear |
| 0.6   | stage 1 appears (per column, staggered) |
| 0.9   | data dot moves toward stage 1 (animateMotion, staggered begins) |
| 1.2   | stage 2 appears |
| 1.5   | stage 2 activates (highlight/pulse on accent) |
| 1.8   | result + response appears |
| 2.1   | best-for panel fades in |
| 2.6   | stable final state |
| 2.8   | loop (T = 2.8s, `repeatCount="indefinite"` on every animation) |

- Column storylines overlap slightly (col 2 starts +0.5s after col 1, col 3
  +1.0s) for a natural feel instead of mechanical row-by-row.
- Any stage is legible if the GIF is paused at that moment (each stage stays
  visible once shown — fadeFrom, not blink).
- Built with the phase builder (`phaseCurve`) so timings are one table, not
  scattered keyTimes strings.
- Respect the README SMIL gotchas: `<animate>` inside the element it animates;
  zero-length keyTimes for instant steps; uniform `dur="T" repeatCount="indefinite"`.

### 4.4 `gen.ts` — assembly
Thin entry point: import theme + content + layout + animation, emit SVG via
`svg.ts`. This is the file an LLM reads first; its structure should answer
"what it says / where it is laid out / how it animates / how it is exported"
without reading generated SVG.
